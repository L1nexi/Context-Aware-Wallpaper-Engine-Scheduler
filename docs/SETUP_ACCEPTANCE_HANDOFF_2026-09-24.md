## 接手时的工作边界

1. 先读用户下一条具体反馈及 [验收问题列表](ACCEPTANCE_ISSUES.md)，只挑对应项处理，并同步更新该项状态。未复现的原因只记为观察或待核实。
2. 测试检验公开行为：后端从 Bottle HTTP 接口观察，只替换外部天气或定位请求；前端从实际设置页交互观察，只替换本地 API 响应。用户已明确，测试样例是否避开实现耦合反模式比红绿流程更重要；不为简单透传和纯实现细节添加测试。
3. 不覆盖或清空真实 `config/profile.json`；手工首次启动验证使用独立临时配置目录。日志、截图和测试数据不得泄露 API Key 或公网 IP。
4. 常用验证：`.\scripts\test.ps1 -q`；前端目录运行 `npm run test:e2e`、`npm run type-check`、`npm run build-only`；Python 修改后运行虚拟环境中的 Ruff。只对受影响范围做必要验证。
5. 当前启动命令是 `python main.py`；前端联调可用 `python main.py --api-port 38417` 配合前端 `npm run dev`。旧六 YAML 配置命令行已退出正式路径。打包命令 `.\scripts\build.bat` 属于单独的发布收尾；冻结包曾完成静态资源与本地服务冒烟验证，真实桌面和目标网络验收仍未完成。

按 `$frontend-design` 与 `$shadcn-vue` 核查了当前设置页，并在 1200×780 深色浏览器视口使用本地 API 模拟数据查看了 Wallpaper Engine、天气和场景页。用户随后要求先修明确的不规范之处；以下分别记录已修部分和仍需用户参与的设计判断。

- **已修复，待真实窗口验收**：`SceneBindingsStep.vue` 的播单选择框限制在场景行内，约 170 字符的播单名不再造成内容区横向溢出；选项写明“张壁纸”。单个绑定缺失或已失效时，该 `Field`、`SelectTrigger` 和就地错误信息会指明问题。前端交互用例覆盖以上公开行为。
- **已修复的组件与可访问性问题**：主工作区使用 `CardHeader`／`CardTitle`／`CardDescription`，每页只显示一份标题；天气指引的 `space-y-*` 已换成 `flex`／`gap-*`。中文辅助标签已本地化；播单扫描使用 shadcn-vue `Table` 和表头，最终检查页使用语义化键值列表。
- **新增外观切换**：设置页侧栏提供“跟随系统／浅色／深色”，沿用现有 shadcn-vue `ToggleGroup` 和 Tailwind 语义色；VueUse 将选择保存在本机 `localStorage`，与 Profile 草稿分离。浏览器交互测试覆盖切换、重开后保留、系统偏好变化，默认 1200×780 视口已查看浅色和深色截图；原生窗口仍待用户验收。
- **仍待用户参与的视觉判断**：天气指引在默认高度下需滚动才能看到最后一步，异常提示常驻，主要操作与辅助排错信息层级仍可能偏弱。是否收起辅助内容应结合用户下一轮截图决定。
- **侧栏视觉调整，待真实窗口验收**：中英文切换移至侧栏底部，与图标外观入口并排；左侧分类只保留图标和名称，移除顶部流程说明及每项的副文案。品牌名与工作区标题的字号更接近，非保存状态的“检查并完成／保存”入口改为次要样式。工作区现有说明文案按用户决定暂时保留，后续由用户逐页调整。

已有符合规范的基础：组件配置为 Vue 3、Tailwind v4、`reka-rhea`、Lucide；大多数字段使用 `Field`／`FieldGroup`，选择器项目置于 `SelectGroup`，按钮用内置变体，主题使用语义色，状态提示使用 `Alert`／`vue-sonner`，并有减少动态效果的全局处理。界面视觉是否足够体现 Wallpaper Engine 本地调度器的特点，属于需用户参与的设计判断，不以自动化检查判定通过。
