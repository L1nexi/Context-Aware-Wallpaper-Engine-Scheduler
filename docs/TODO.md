# 后续小版本待办

以下改进暂不阻塞当前产品化阶段。已有实现的真实桌面与目标网络验收事实仍见 [验收问题列表](ACCEPTANCE_ISSUES.md)。

- [ ] **天气运行状态可视化（A-01）**：现有脱敏日志和天气校验反馈暂时够用。后续若实际排障需要，再设计已生效配置的天气健康状态、失败与恢复事件，以及设置页入口。
- [ ] **核对天气告警与修改操作的关系（A-02）**：仅在可复现时对齐提交响应、Profile 应用和天气抓取记录；目前没有证据表明错误草稿影响了运行。
- [ ] **保留最大化状态（A-09）**：托盘再次聚焦设置窗口时，不应使已最大化窗口恢复为普通大小。
- [ ] **即时保存外观偏好**：切换“跟随系统／浅色／深色”后立即记住，关闭设置窗口或重启程序后仍保留。沿用现有 pywebview 原生桥接，独立于需要显式保存的 Profile；浏览器开发环境保留本地存储。实现后在真实窗口验证关闭重开与程序重启。
- [ ] **重新确定产品名称与图标**：由用户先确定新的名称和图标方向，再统一检查界面、托盘、窗口标题、发布包和文档中的相关标识。
- [ ] **调查窗口图标未生效**：当前观察是设置窗口未显示预期的自定义图标。打包可能有关，但原因尚未确认；分别核对源码运行和打包运行时的图标资源、路径与设置时机。
- [ ] **调整响应风格文案（A-12）**：明确“背景优先”“当前优先”的用户语义后，再修改界面用词。
- [ ] **校准响应风格预设**：现有权重可作为当前版本的暂定值；后续按实际使用反馈调优，并使 `tools/tuning` 与 Profile 配置层对齐。
- [ ] **复核已实现的设置体验（A-03～A-08、A-10～A-11）**：手动天气校验、错误提示、密钥指引、位置估算、播单与默认场景、保存提示和自由跳转均有当前实现；后续根据真实桌面和目标网络反馈逐项调整，不因暂缓而记为已验收。
- [ ] **审查历史日志的敏感信息（A-13）**：分享旧日志前先脱敏；后续单独核对日志输出边界。
